# اسکرپر جست‌وجوی دارو در ایران

این پروژه یک اسکرپر پایتونی برای جست‌وجوی اطلاعات دارو و محصولات دارویی/سلامتی در فروشگاه‌های آنلاین ایرانی است.

## قابلیت‌های فعلی

- جست‌وجوی نام دارو با زبان فارسی
- نرمال‌سازی حروف فارسی و عربی
- نرمال‌سازی اعداد فارسی و عربی
- تطبیق هوشمند نام محصول و کاهش نتایج نامرتبط
- استخراج نام محصول
- استخراج برند
- استخراج توضیحات
- استخراج قیمت
- تشخیص واحد پول
- تشخیص وضعیت موجودی آنلاین
- ثبت متن/دلیل تشخیص موجودی
- استخراج لینک مستقیم محصول
- ثبت نام سایت، آدرس و تلفن
- ثبت امتیاز تطابق
- ثبت زمان بررسی
- مدیریت خطای هر سایت به صورت مستقل
- Retry برای بعضی خطاهای موقت HTTP و Timeout
- اجرای هم‌زمان درخواست‌ها
- گروه‌بندی نتایج مشابه
- تست واحد
- تست زنده روی صفحات واقعی اینترنت
- اجرای خودکار تست‌ها با GitHub Actions
- تولید گزارش JSON از تست زنده

> قیمت و موجودی فقط وضعیت مشاهده‌شده در زمان بررسی هستند. موجودی آنلاین لزوماً موجودی فیزیکی داروخانه نیست. وجود صفحه فروش اینترنتی برای داروی نسخه‌ای نیز به معنی مجاز بودن فروش بدون نسخه نیست.

## منابع فعلی

- مثبت سبز
- داروکالا
- دارولاین
- مفیدطب
- داروهوم

برای هر منبع Adapter مستقل وجود دارد تا منطق مخصوص همان سایت از هسته اصلی جدا باشد.

## وضعیت فعلی منابع

### داروکالا
جست‌وجوی واقعی و استخراج صفحه محصول فعال است. در تست زنده، صفحه واقعی محصول با HTTP 200 دریافت شده و قیمت و موجودی استخراج شده است.

### داروهوم
جست‌وجوی واقعی و استخراج محصول فعال است.

### مثبت سبز
در GitHub Actions در بعضی اجراها با ConnectTimeout مواجه شده است؛ بنابراین این موضوع فعلاً به عنوان مشکل دسترسی محیط تست در نظر گرفته می‌شود و نباید آن را قطعی به معنی از کار افتادن سایت دانست.

### مفیدطب
مسیر جست‌وجوی فعلی بررسی شده ولی endpoint آزمایش‌شده پاسخ 404 می‌دهد. تکمیل Adapter نیازمند پیدا کردن مسیر/API واقعی جست‌وجوی سایت است.

### دارولاین
نتایج جست‌وجو به صورت Dynamic تولید می‌شوند و HTML خام همیشه برای استخراج نتیجه کافی نیست. مرحله بعدی بررسی API داخلی یا روش مناسب استخراج داده‌های Dynamic است.

## نمونه نتیجه تست زنده

در یکی از تست‌های واقعی، محصول «کپسول مگنیفورت آرین سلامت سینا» از داروکالا با اطلاعات زیر Parse شد:

- HTTP: 200
- قیمت استخراج‌شده: 3,799,000
- موجودی: ناموجود
- شواهد موجودی: ناموجود

همچنین یک محصول مگنیفورت از داروهوم با قیمت 4,000,000 و وضعیت «اتمام موجودی» شناسایی شد.

## توضیح فایل‌های اصلی

### scraper.py
هسته اصلی برنامه است و وظایف دریافت صفحات، جست‌وجو، Parse، تطبیق نام، استخراج قیمت و موجودی، مدیریت خطا و اجرای هم‌زمان را انجام می‌دهد.

### config.py
منابع، URLهای جست‌وجو، Adapterها، Timeout و تنظیمات عمومی در این فایل قرار دارند.

### models.py
ساختار داده محصولات و پیشنهادهای فروش را تعریف می‌کند.

### aggregator.py
نتایج چند سایت را جمع‌آوری و محصولات مشابه را گروه‌بندی می‌کند.

### sources/
منطق اختصاصی هر سایت در این پوشه قرار دارد.

### tests/
تست‌های واحد و تست‌های Live پروژه در این پوشه قرار دارند.

## نصب

پیش‌نیاز: Python.

بررسی نسخه در Windows:

    py --version

نصب وابستگی‌ها:

    py -m pip install -r requirements.txt

در صورت نبودن دستور py:

    python -m pip install -r requirements.txt

Linux/macOS:

    python3 -m pip install -r requirements.txt

## اجرا

اجرای CLI:

    py cli.py

یا:

    python cli.py

اجرای نقطه ورود اصلی:

    py main.py

پس از اجرا می‌توانید نام دارو را وارد کنید؛ برای مثال:

    مگنیفورت

## اجرای تست‌ها

تست‌های واحد:

    python -m pytest -q

تست زنده:

    python -m pytest tests/test_live.py -q -s

تست Live به اینترنت نیاز دارد و صفحات واقعی منابع را بررسی می‌کند.

## گزارش Live

تست زنده فایل زیر را تولید می‌کند:

    live_report.json

گزارش شامل Query، زمان بررسی، تعداد نتایج، وضعیت منابع، نتایج محصولات، قیمت، موجودی، خطاها و اطلاعات تشخیصی صفحات جست‌وجو است.

## GitHub Actions

### Python Tests

فایل:

    .github/workflows/test.yml

تست‌های اصلی پروژه را اجرا می‌کند.

### Live Smoke Test

فایل:

    .github/workflows/live-smoke.yml

وابستگی‌ها را نصب کرده، تست واقعی اینترنتی را اجرا می‌کند و گزارش live_report.json را به عنوان Artifact نگهداری می‌کند.

## معماری Adapter

ساختار پروژه Modular است. هر سایت می‌تواند Parser مخصوص خود را داشته باشد.

Adapter پایه شامل منطق‌هایی مانند:

    build_search_url()
    search_links()
    parse_product()
    source_meta()

است.

این طراحی باعث می‌شود با تغییر HTML یا API یک سایت، لازم نباشد کل پروژه تغییر کند.

## تطبیق نام دارو

برای کاهش False Positive، علاوه بر WRatio از بررسی پوشش کلمات نیز استفاده می‌شود.

حداقل امتیاز فعلی:

    68

هدف این بخش جلوگیری از نمایش محصولاتی است که فقط شباهت متنی ضعیفی با عبارت جست‌وجو دارند.

## استخراج قیمت

قیمت ابتدا از JSON-LD و اطلاعات ساختاریافته صفحه بررسی می‌شود و سپس الگوهای متنی شامل تومان، تومن و ریال بررسی می‌شوند.

در توسعه بعدی قیمت فروش آنلاین، قیمت مرجع و تخفیف باید به صورت فیلدهای جداگانه نگهداری شوند.

## تشخیص موجودی

عبارت‌هایی مانند موارد زیر تشخیص داده می‌شوند:

مثبت:
- موجود در انبار
- در انبار موجود است
- موجود است
- افزودن به سبد خرید
- In Stock
- Add to Cart

منفی:
- ناموجود
- اتمام موجودی
- در انبار موجود نیست
- در انبار موجود نمی باشد
- Out of Stock
- Sold Out

اگر شواهد کافی وجود نداشته باشد وضعیت «نامشخص» ثبت می‌شود.

## وضعیت منابع

برای هر سایت یکی از وضعیت‌های زیر ثبت می‌شود:

- ok
- partial
- error

همچنین تعداد لینک‌های پیدا شده، تعداد محصولات Parse شده، صفحات ناموفق، HTTP status و خطا ثبت می‌شوند.

خطای یک منبع باعث توقف کل جست‌وجو نمی‌شود.

## محدودیت مهم درباره موجودی

وجود صفحه محصول با «موجود بودن» یکسان نیست.

سه وضعیت باید از هم تفکیک شوند:

1. صفحه محصول وجود دارد.
2. سایت برای محصول قیمت نمایش می‌دهد.
3. سایت محصول را موجود اعلام می‌کند.

موجودی فیزیکی داروخانه فقط در صورتی قابل تأیید است که منبع اطلاعات موجودی واقعی یا لحظه‌ای ارائه کند.
